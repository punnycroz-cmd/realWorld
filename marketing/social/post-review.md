# Post review — the weekly social retro

**Status: v139 — fill-in template + decision rules. LOCAL ONLY.**

Runs every week after launch (with the ANALYTICS.md weekly report —
that doc measures the funnel; this one measures *posts*). Thirty
minutes, one table, three decisions. The goal: the draft bank gets
smarter every week instead of just older.

---

## 1. The scorecard (copy per week)

| Post (link) | Channel | Draft ID | Impressions | Profile taps / link clicks | CTR | Watch-start conv.* | Verdict |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

*watch-start conversion = analytics `watch_start` events attributed to
the post's UTM. If the funnel isn't live yet, leave the column blank —
do not estimate. A missing column is honest; a guessed one isn't.

Draft ID = the bank label (M1–M11, R1–R6, P1–P8, clip numbers, arc
post numbers). Posts written off-bank get `adhoc` — and a note on
whether the copy is worth banking.

## 2. Verdict rules (relative, not absolute — no invented benchmarks)

Sort each channel's posts by CTR within the week:

- **Top quartile → RERUN.** The format works. Schedule a variant in a
  future slot (same skeleton, new moment). Log why it won in one line
  ("concrete minute-count beat the concept post" — the reason matters
  more than the win).
- **Middle → KEEP.** Leave in rotation; no edit.
- **Bottom quartile → KILL or FIX.** If the *format* failed twice in a
  row, kill it (strike the draft in the bank with a dated note, don't
  delete — history is useful). If the *asset* failed (bad still, weak
  clip), fix the asset and retry once.
- **Zero-engagement posts on launch week don't count.** The sample is
  too small; re-run before judging.

Absolute floors that override the quartile rules:
- Any post that drew corrections in comments → audit against §8; if
  the copy overclaimed, fix the *draft file* same week.
- Any reshare (R-bank) underperforming plain replies three weeks
  running → prefer replying; note it in `reshare-playbook.md` §6.

Standing permissions live here so future versions don't re-ask.
Deletion requests get their own line: `Status = revoked — reshare
removed YYYY-MM-DD`.

## 4. The three weekly decisions

End every retro with explicit answers:

1. **What runs again?** (rerun verdicts → next week's calendar slots)
2. **What gets edited?** (draft-file fixes logged here and applied to
   `social/drafts/` same week — the bank is code, not scripture)
3. **What's missing?** (a comment type we couldn't answer from
   `reply-bank.md`, a moment with no draft — file it for the next
   marketing iteration; this is how the bank grew arcs at v34–v124)

## 5. Where the notes live

A dated `## week N` block appended below this file's header keeps the
whole retro in one place; the summary line also goes in MARKETINGLOG.md
per the weekly-metrics note in SOCIAL-LAUNCH-PLAN §6.4.
